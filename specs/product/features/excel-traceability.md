# Excel Traceability

This feature keeps table templates unchanged while giving reviewers a direct path from each displayed value to its evidence.

## Requirement

When an table is generated, every final data point shown in the table template must be traceable from the value cell itself. The template layout must not gain extra trace columns, evidence columns, or helper fields.

The actual extracted value should be stored only in the `Evidence` sheet. The table template cell should display that value by referencing the `value` cell in the matching evidence row, and the same template cell should be an internal table hyperlink to the first cell of that evidence row.

Example:

```text
Evidence!D24 contains "Yes"
Output!D12 displays the value from Evidence!D24
Clicking Output!D12 opens Evidence!A24
Evidence!A24 contains evidence_id "EV-000023"
```

The output cell can use an Excel formula in this shape:

```excel
=HYPERLINK("#'Evidence'!A24",'Evidence'!D24)
```

This avoids duplicating the displayed value. If the value in `Evidence!D24` changes, the visible value in `Output!D12` changes with it.

## Minimal Evidence Table

The table should include an `Evidence` sheet with one row per traceable output value.

Required columns:

| Column | Meaning |
| --- | --- |
| `evidence_id` | Stable identifier for this evidence row, generated by the table tool, for example `EV-000023`. |
| `output_sheet` | Sheet containing the displayed audit value. |
| `output_cell` | Cell containing the displayed audit value and hyperlink. |
| `value` | The extracted value. Table template cells display this cell by reference. |
| `source_type` | Current the product value is `sql`. |
| `source_table` | SQL table used as source evidence. |
| `source_column` | SQL column used as source evidence, or the primary column for aggregate metrics. |
| `source_record_id` | Source row identifier; use `multiple` for aggregate values and `not_applicable` when no single row applies. |
| `extraction_method` | Execution tool used, for example `sql_execute`. |
| `extracted_at` | Timestamp when the value was extracted. |

Optional later columns can include query name, validation status, confidence, issue id, generated SQL hash, or task contract reference.

## Tool Plan

Add a dedicated table/XLSX tool instead of relying on free-form skill instructions.

Tool name:

```text
table_add_evidence
```

Purpose:

```text
Append audit evidence to an existing XLSX table and mirror each evidence value into the requested template cell.
```

Inputs:

```json
{
  "path": "runs/<run-id>/result.xlsx",
  "records": [
    {
      "output_sheet": "Output",
      "output_cell": "D12",
      "value": "Yes",
      "source_type": "sql",
      "source_table": "medications",
      "source_column": "description",
      "source_record_id": "abc123",
      "extraction_method": "sql_execute",
      "extracted_at": "2026-05-26T10:15:00Z"
    }
  ]
}
```

Behavior:

1. Open the existing XLSX table.
2. Create the `Evidence` sheet if it does not exist. The sheet name is fixed and must not be configurable.
3. If `Evidence` already exists, validate that its header matches the expected evidence columns.
4. Generate new `evidence_id` values inside the Python tool by continuing from the highest existing `EV-000001` style ID.
5. Append the evidence records after existing evidence rows.
6. For each record, verify that `output_sheet` exists and `output_cell` is a valid A1 coordinate. The output cell does not need to already exist inside the sheet's current used range.
7. Write the extracted value only into the `value` column of the matching evidence row.
8. Replace each `output_cell` with a formula that displays the evidence row's `value` cell and links to the first cell of the evidence row.
9. Do not add trace columns, evidence columns, comments, shapes, or visible helper fields to the table template sheets.
10. Save the table in place to `path`.

Expected hyperlink form:

```excel
=HYPERLINK("#'Evidence'!A24",'Evidence'!D24)
```

Validation output:

```json
{
  "toolName": "table_add_evidence",
  "tablePath": "runs/<run-id>/result.xlsx",
  "evidenceSheetName": "Evidence",
  "recordsWritten": 42,
  "formulasWritten": 42,
  "evidence": [
    {
      "evidence_id": "EV-000023",
      "output_sheet": "Output",
      "output_cell": "D12",
      "evidence_cell": "'Evidence'!A24",
      "value_cell": "'Evidence'!D24"
    }
  ],
  "validation": {
    "missingOutputSheets": [],
    "invalidOutputCells": [],
    "invalidOutputFormulas": [],
    "headerErrors": [],
    "brokenEvidenceTargets": []
  }
}
```

The tool must fail when the evidence header is incompatible, an output sheet is missing, an output cell is invalid, or an output formula cannot be created to point at the matching evidence row. The agent must not provide `evidence_id` or `trace_id`; evidence IDs are generated by the Python tool. A table should not be saved with unresolved validation errors.

## Future Usage Rule

When this feature is implemented, table generation should collect source values, call `table_add_evidence`, append those values into the `Evidence` sheet, and set each table template output cell to a hyperlink formula that displays the associated evidence `value` cell.

The implementation must not satisfy this requirement by adding a `Trace`, `Evidence`, or `Trace ID` column to a structured table template.
